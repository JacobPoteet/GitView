Made for a fleet

Other clients open one repository at a time. You keep twenty.

The question you ask in the morning is which of your projects need you today. GitView answers it on the first screen, then leaves the commands to you.

The fleet is the home screen

The scanner reads branch, ahead and behind, dirty files, stashes and merged branches for each repository, and streams the rows in as it goes. A cold start paints the list from SQLite before it opens a single repository.

Every button shows its command

Hover to read it, click to run it in that repository’s shell, or shift-click to type it at the prompt and edit it before you press Enter. You keep the habit of typing git, and the buttons make it faster.

Nothing is generated for you

There is no commit-message AI, no agent panel, no account and no telemetry. Repository reads go through libgit2, and anything that touches a remote shells out to git.exe, so your credential helper and SSH agent keep working.

Built for the solo dev with too many repos

Sync the whole fleet from one button.

  • Sync and prune across repositories. The transcript keeps each command as typed, its exit code and its output, so you can read what ran and copy a line out of it. The batch reads each repository again between commands, since a fetch changes what the pull should do.
  • A sort that knows what needs you. Behind, dirty, a paused rebase, and commits that exist only on this disk on any local branch. GitView fetches on launch, so the ↓ counts are today’s.
  • Pin what you work on, archive the rest. A hidden repository drops out of the sweep, the inbox and the Ctrl+K palette. A hidden npm script leaves the palette too.
  • GitView finds the tasks. package.json, Cargo.toml, Makefile, justfile, pyproject.toml, .csproj, CMakeLists.txt, Compose files, Unity projects, and a checked-in gitview.toml for the script none of those cover.

The terminal is the app

One shell per repository, and it outlives the view.

Switch projects and come back: the scrollback and the dev server you left running are still there. Close the app and reopen it, and the scrollback is too.

  • Command blocks. PowerShell tells GitView where each command started and how it exited. A bar in the scrollback turns green or red with the exit code, and violet while the command runs.
  • Ports as chips. A running command prints localhost:5183 and GitView shows it as a chip. Click it and GitView types Start-Process, the same as any other button.
  • Keep a command you already ran. One button saves the last block as a task for that repository. GitView writes nothing into the repository itself.
  • Scrollback across restarts. Each shell’s buffer goes to disk as it settles and on close, and comes back above the next launch’s first prompt. Ctrl+F searches it, and a second shell keeps git free while the first one runs the dev server.
  • Your prompt survives. Starship and oh-my-posh keep working. GitView wraps the prompt in memory and writes nothing to your profile.

01 · the whole history

Every commit on every branch

GitView draws the lanes on a canvas under rows that exist only while they are on screen. It packs the lanes in Rust and reads 5,500 commits at 140 ms a page, whichever page you scroll to.

02 · the filter

Narrow it the way git log would

Type words to match the message, author: for a name, path: for a file or a folder. History of this file, on any file row, is the same filter with the path filled in.

03 · one commit

Its files and its hunks

Click a row to read the commit in the pane, or shift-click to type git show. Right-click offers revert, cherry-pick and reset, each typed at the prompt. A signed commit wears a mark; GitView reads that the signature is there and leaves checking it to git verify-commit.

04 · blame

Who wrote each line, and when

The gutter groups lines by the commit that last touched them and tints each group by age in the accent’s hue, brightest for the newest. Click a sha to open that commit on the same file.

05 · one hunk

Stage a hunk you can’t type

A hunk is the one argument nobody can type at a prompt. GitView writes it to a patch under its own data folder and types git apply --cached against that path, which is what git add -p does underneath. The scrollback keeps the command.

06 · a paused rebase

The state a prompt hides

With nothing conflicted, a paused rebase looks like a detached HEAD. GitView reads the state and keeps a strip under the header, with git’s own next steps as buttons. Continue and Skip type straight away. Abort asks first, because it throws away what you resolved.

GitHub, without the browser

Reads GitHub out of sight, writes to it by typing.

One aliased GraphQL query through gh pulls the pull requests, issues and check runs for the whole fleet. gh holds the token; GitView has no HTTP client and no place to store one.

  • The inbox. Open pull requests, issues and check runs from all your repositories in one list, grouped by repository. A pull request names the issues it closes, and an issue names its pull request.
  • The PR desk. Push, open a pull request from a form, watch the checks by name, then merge and delete the branch. Merge stays off, with the reason, for a draft, a conflict or a branch behind. Each step goes into that repository’s shell as a gh command.
  • Updates that name their command. GitView checks its own latest release through gh release view and hands you the gh release download line to run yourself.

How it’s built

It reads in process and writes through the tools you already trust.

Tauri v2, a Rust core and a React front end. One rule decides which process each call reaches, and that rule is why GitView holds no credentials: credential helpers, SSH agents and GitHub tokens stay with the tools that already own them.

How a change gets checked

Every bug found in GitView so far passed clippy, cargo test, a full CI build and a read-through, then showed up within minutes of opening the window. A pull request ends with the real app driven over the WebView’s debugging port, against throwaway repositories built for the case: an unrelated history, a paused rebase, six branches alive at once, 5,500 commits from git fast-import.

Each pull request updates the wiki note that owns what changed, and a number in the wiki is a measurement. The page you are reading follows the same rule: every figure on it came from the app, the repository or the log.
